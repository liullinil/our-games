## 1. Что уже сделано

### 1.1. У игры больше нет диапазона лет

Владелец: «В играх не имеет смысла писать с какого по какой год была игра.
Важна дата выхода и всё».

- Из схемы игр (`src/content.config.ts`) убрано поле `years.end`. Осталось
  `years.start` (год выхода) и `years.note` (пояснение).
- Поле `end` вычищено из 30 файлов игр; там, где оно несло смысл (закрытие
  серверов), факт перенесён в `years.note`.
- `yearsLabel()` в `src/lib/labels.ts` заменена на `yearOf()` — она печатает
  один год. Переименование прошло по всем 11 файлам, которые её звали.
- `scripts/validate-content.mjs` теперь ругается на возвращённое `years.end`,
  чтобы поле не вползло обратно.
- Карточка игры и карта больше не рисуют отрезок: длина карточки на карте
  зависит только от длины надписи.

### 1.2. Новые поля статьи об игре

Владелец: «Отзывы, интересные факты, обзоры, выходила ли вне РФ тоже,
интересные механики и пасхалки»; «Можно давать ссылки на DTF и другие сайты,
где есть обзоры и механики»; «Если игры есть в публичном доступе — обязательно
укажи. Если можно по лицензии скачать и распространять — залей к нам на сайт».

В схему игр добавлены:

| Поле | Что это |
| --- | --- |
| `specs.abroad` | выходила ли за пределами России и СНГ, под каким именем, с каким издателем |
| `reviews[]` | рецензии прессы: `outlet`, `score` (строкой, как у издания), `verdict` (пересказ своими словами), `url`, `author`, `date` |
| `reading[]` | что почитать дальше: DTF, StopGame, Хабр — `title`, `url`, `outlet`, `note` |
| `availability` | где взять игру: `status`, `note`, `where[]` (магазины, архивы, репозиторий), `files[]` (файлы у нас) |

`availability.status` — одно из `sold`, `free`, `freeware`, `opensource`,
`unavailable`, `unknown` (расшифровка в схеме и в `docs/authoring.md`).

**Про раздачу файлов.** Схема и страница это поддерживают: файл кладётся в
`public/downloads/<id>/`, `availability.files[]` описывает лицензию и источник,
валидатор проверяет, что файл есть на диске и что `status` — `freeware` или
`opensource`. Кнопка «Скачать» с условиями рядом уже рисуется. **Но ни одного
файла ещё не залито**: агентам запрещено заполнять `files` самостоятельно, они
только сообщают кандидатов в отчёте. Решение по каждому файлу — за человеком.

### 1.3. Иллюстрации внутри текста статьи

Владелец (дважды): «В статьях нужно много картинок, прямо в тексте, а не
только отдельным блоком»; «иллюстрации нужны прямо в текстах статей».

- `src/lib/article.ts` — `planArticle()`: режет готовую разметку статьи по
  заголовкам `<h2>` и раскладывает медиа. Правила: вступление без картинки
  (над ним постер), постер в тексте не повторяется, в раздел про игровой
  процесс идёт геймплейный ролик, остальным разделам — по кадру.
- `src/components/ArticleBody.astro` — рисует текст с кадрами и роликом.
  Через одну картинка уходит на поля (`float` при ширине от 1240px).
  Подпись с правообладателем и ссылкой на источник стоит под каждым кадром.
- Постер получил собственную подпись с правами и больше не дублируется
  в галерее; галерея под статьёй показывает только остаток.
- Лайтбокс общий: кадры в тексте и в галерее листаются вместе.

Проверено на сборке: в статье о S.T.A.L.K.E.R. пять кадров разошлись по
пяти разделам.

### 1.4. Геймплейные ролики в текст

Владелец: «постарайся добавлять gameplay видосики тоже в статьи».

Код готов: `planArticle()` находит ролик с приметой геймплея в названии

**Но данных не хватает: у 136 игр из 173 нет ни одного геймплейного ролика** —

### 1.5. Родство студий

Владелец: «Студии лучше располагать рядом друг с другом на карте, если есть
много общих игр — они переименовываются и распадаются очень часто».

- В схему студий добавлено поле `related[]`: `studio`, `kind`

Сейчас семьи собираются только по связям между играми.

## 2. Главная нерешённая задача: карта

Отзыв владельца, дословно:

> «Карта никуда не годится, бессмысленная по задумке. Надо что-то придумать
> с ней. Студий много, в основном по 1-2 игры у них. Временной промежуток
> короткий. Получается длинная узкая полоса, которой неудобно пользоваться».

Цифры, которые объясняют беду: 173 игры, 106 студий, у 54 из них ровно одна
игра; годы 1974–2024, то есть полсотни колонок. При раскладке «строка =
студия» получается полотно в полторы сотни дорожек высотой и полсотни лет
шириной — читать его нечем.

Переписанная карта (1.6) проблему только смягчает: семьи и полки жанров
убирают пустые строки, но сама идея «студии по вертикали, годы по
горизонтали» остаётся. Владелец забраковал именно идею, а не исполнение.
**Не нужно доводить нынешнюю карту — нужно предложить другую и согласовать.**

Направления, которые стоит обсудить (ни одно не выбрано):

1. **Лента времени плиткой.** Колонка — год или пятилетка, внутри колонки
   карточки лежат плиткой сверху вниз. Высота определяется самым густым
   годом, а не числом студий. Связи рисуются при наведении, а не все сразу.
2. **Строка — эпоха или жанр.** Пять эпох или десять жанров вместо сотни
   студий. Студия остаётся подписью на карточке и фильтром.
3. **Граф вместо хронологии.** Кластеры по семьям студий и сериям, год —
   цвет или радиус. Тогда студии-однодневки не создают пустых строк.
4. **Несколько маленьких карт вместо одной большой.** Карта эпохи на
   странице эпохи, карта серии на странице серии, карта семьи студий на
   странице студии. Общая карта тогда нужна только как обзор.
5. **Карта как поиск, а не как картина.** Фильтры (жанр, эпоха, платформа,
   студия) сверху, результат — плотная сетка карточек; связи показываются
   для выбранной игры.

Что уже есть и переиспользуется при любом выборе: `src/lib/families.ts`
(семьи студий), `src/lib/relations.ts` (четыре вида родства и рёбра),
`src/lib/graph-sprite.ts` (лист миниатюр, одна картинка на всю карту),
`src/lib/layout.ts` (укладка по дорожкам и ступенчатые рёбра),
`/graph-cards.json` (данные карточки предпросмотра).

Мини-карта на странице игры (`src/components/MiniMap.astro`) построена на
тех же кирпичах и, скорее всего, тоже потребует переделки вслед за большой.

## 4. Как всё проверять

```bash
node scripts/validate-content.mjs   # схема, годы, рецензии, файлы раздачи
node scripts/check-links.mjs        # относительные ссылки внутри статей
npx astro check                     # типы
npm run build                       # связи между записями
npm run coverage                    # где статьи, кадры и видео, а где пробелы
```

Предпросмотр собранного сайта (так же, как на GitHub Pages):

```bash
npm run serve:pages
```

Страница открывается на `http://localhost:4330/our-games/`. Карта —
`/our-games/graph/`, образцовая статья — `/our-games/games/35mm/`.
