# Как писать статьи для «Игростроя»

Энциклопедия компьютерных игр СССР, России и соседних стран. Сайт статический
(Astro), контент лежит в `src/content/`:

| Папка | Что | Формат |
| --- | --- | --- |
| `games/<id>/index.md` | игры | frontmatter + текст статьи |
| `studios/<id>/index.md` | студии и издатели | frontmatter + текст |
| `platforms/<id>/index.md` | платформы (компьютеры, приставки, телефоны) | frontmatter + текст |
| `engines/<id>.md` | движки | frontmatter + текст |
| `series/<id>.yaml` | серии игр | только карточка |
| `eras/<id>.yaml` | эпохи | только карточка |

Схемы всех полей — в `src/content.config.ts`. Идентификаторы (имена папок и
файлов) менять нельзя: на них ссылаются другие записи. Ссылка на несуществующую
запись роняет сборку.

## Общие правила

1. **Язык — русский**, стиль энциклопедический, но живой: как хорошая статья
   в журнале, а не как реферат. Короткие абзацы, конкретные факты, без воды и
   без рекламных эпитетов («уникальный», «легендарный» — только если так
   называют источники). Кавычки «ёлочки», тире «—», буква «ё».
2. **Факты проверяются.** Годы, студии, платформы, издатели, движки, продажи и
   оценки — только из источников: русская и английская Википедия, MobyGames,
   StopGame, DTF, «Канобу», официальные сайты, интервью разработчиков. Сначала
   ищите (WebSearch), потом читайте страницу (WebFetch). Если источники
   расходятся, так и пишите: «Википедия даёт 2004 год, MobyGames — 2005».
   Число без источника не пишется вообще. Ничего не выдумывать: нет данных —
   нет фразы.
3. **Источники обязательны**: в `sources:` 2–5 записей с `title` и `url`.
   Для книг и журналов — `author`, `publisher`, `year`, `pages`.
4. **Ссылки внутри текста** — относительные, только на существующие записи:
   со страницы игры `../vangers/` (другая игра), `../../studios/kd-lab/`,
   `../../engines/x-ray/`, `../../platforms/dendy/`, `../../series/stalker/`,
   `../../eras/nineties/`. Со страницы студии: `../../games/vangers/`,
   `../nival/`. Со страницы движка (`engines/x-ray.md`, адрес `/engines/x-ray/`):
   `../../games/stalker-shoc/`, `../../studios/gsc-game-world/`. Список
   существующих идентификаторов: `ls src/content/games`, `ls src/content/studios`
   и так далее. Проверка: `node scripts/check-links.mjs`.
5. **Frontmatter не ломать.** YAML: строки с двоеточием, решёткой, кавычками
   или начинающиеся с спецсимвола берите в двойные кавычки; `summary: >-` —
   блок с отступом в два пробела. После правок запускайте
   `node scripts/validate-content.mjs` — он ловит сломанный YAML и пропущенные
   поля. **`npm run build` не запускать**: сборку делает ведущий, параллельные
   сборки ломают друг друга.
6. **Поля `poster:` и `gallery:` не трогать**: их заполняют скрипты
   (скриншоты из Steam и Википедии, ролики). Если они уже есть в файле —
   оставить байт в байт. Если файл переписывается целиком, сначала прочитать
   его и перенести эти блоки без изменений.
7. Не запускать `node scripts/seed/generate.mjs`: реестр заготовок больше
   не источник правды, источник правды — файлы в `src/content`.

## Статья об игре

Что можно менять в frontmatter:

- `altNames` — дополнить вариантами названия (английское, рабочее, сокращение).
- `years.start` — год первого релиза на любой платформе; если в заготовке
  ошибка, исправить и указать источник. `years.end` — только для игр с долгой
  жизнью: последняя большая версия, закрытие серверов; `null` — живёт сейчас.
  Для игры, вышедшей один раз, поле `end` не пишется вовсе. `years.note` —
  пояснение («ранний доступ с 2017, релиз в 2025»).
- `platforms`, `engines`, `publishers`, `predecessors`, `series` — исправлять,
  если источники говорят иначе, но только существующими идентификаторами.
  Новых студий, платформ и движков не создавать; если чего-то не хватает,
  написать об этом в отчёте ведущему.
- `specs`: `releaseDate` («20 марта 2007»), `modes` (из single, multiplayer,
  coop, online), `perspective` («от первого лица»), `setting` («Зона отчуждения,
  2012 год»), `sales` (число копий, только с источником) или `salesNote`
  («более 2 млн копий к 2009 году»), `development` («2001–2007»),
  `metacritic` (число). Пример:

  ```yaml
  specs:
    releaseDate: "20 марта 2007"
    modes: [single, multiplayer]
    perspective: "от первого лица"
    setting: "Чернобыльская зона отчуждения, 2012 год"
    salesNote: "более 2 млн копий к 2008 году"
    development: "2001–2007"
    metacritic: 82
  ```

- `summary` — оставить или уточнить: одно-два предложения, что это и чем важно.
- `status: article`, когда текст статьи готов (от 350 слов). Если по игре
  почти нет материала, оставить `card`, но источники и `specs` заполнить всё равно.
- `website`, `steamAppId` — добавить, если нашлись (Steam: число из адреса
  `store.steampowered.com/app/<число>/`).

Текст после frontmatter (350–900 слов для `article`):

```markdown
Вводный абзац без заголовка: что это за игра, кто и когда сделал, чем она
важна. Название студии — ссылкой на её страницу.

## История создания

Кто, зачем, как долго, что мешало. Имена людей — только из источников.

## Игровой процесс

Что игрок делает и чем это отличалось от других игр того времени.

## Выход и приём

Дата, издатель, платформы, продажи, оценки прессы, награды, скандалы.

## Наследие

Продолжения, переиздания, моды, влияние на другие игры, что с игрой сейчас.

## Интересные факты

- Три-пять коротких пунктов, каждый с фактом, а не с оценкой.
```

Разделы можно опускать, если про них нечего сказать; выдумывать нечего.

## Статья о студии

Frontmatter: проверить `names` (цепочка переименований с годами), `city`,
`founded`, `closed`, `kind` (developer / publisher / both), `website`;
исправлять только с источником. Текст 200–500 слов: вводный абзац,
`## История`, `## Игры` (со ссылками на страницы игр), при необходимости
`## Сегодня`. `sources` обязательны.

## Статья о платформе

Frontmatter: `maker`, `years`, `altNames`; фотографию добавляет скрипт
`npm run commons:fetch -- --search "..."` → `--files "File:..." --platform <id>`
(он печатает готовые поля `photo`, `photoCaption`, `photoCredits`; подпись
переписать по-русски, снимок ужать `npm run photos:shrink`). Текст 250–600
слов: вводный абзац, `## Устройство` (что это было технически), `## Игры`
(что и как на ней играли в СССР, России и соседних странах, со ссылками),
`## Наследие`.

## Статья о движке

Frontmatter: `developer` (существующая студия) или `maker` (текст), `origin`,
`tech`, `years`, `website`. Текст 150–400 слов: вводный абзац,
`## Технология`, `## Игры` (со ссылками), `## Судьба`.

## Проверка перед сдачей

```bash
node scripts/validate-content.mjs
node scripts/check-links.mjs
```

Обе команды должны отработать без ошибок.
